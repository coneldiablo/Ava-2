# Собственные расширения AVA: текущая граница

Это исходники **незавершённого** пакета интеграции, не подтверждение готового production-входа.

Отдельное подтверждённое исключение: 17–18.09.2026 принят настоящий вход существующего владельца бизнесa 1 в Twenty через AVA, включая чистый браузер и общий выход. Это `existing_workspace_ui`, а не автоматическое создание любого нового отеля и не приёмка Onyx. [Протокол, ограничения и скриншоты](../docs/acceptance/twenty-entry-2026-09-17/README_RU.md).

- `upstreams.lock.json` закрепляет исходники Twenty `sdk/v2.37.0` и Onyx `v4.7.0`. Сверены пять файлов авторизации/сессий установленного Twenty и три файла установленного Onyx. Это не полная проверка всех зависимостей или всего установленного образа.
- `onyx/ava_namespace.py` вводит обязательный namespace, отдельные имена БД/роли/bucket и запрет выбора чужого поискового индекса. Проверка выполняется до создания поискового клиента. Отдельные роли и ACL PostgreSQL/OpenSearch/MinIO всё равно обязательны; одно имя не обеспечивает изоляцию.
- `onyx/Dockerfile` собирает **только доработку хранения** поверх установленного digest. До изменения проверяет хеши четырёх исходных файлов. Ничего в `ee`, лицензиях и проверках лицензии не изменяет. Этот образ ещё не содержит native-входа покупателя и не должен заменять живую «Аллею».
- `scripts/prepare-onyx-community-extension.py` воспроизводит те же изменения в новом полном дереве upstream из архива с проверенной SHA-256; существующий каталог не перезаписывает. Такое дерево сохраняет notices и исходники для предоставления модифицированного компонента.

AVA module access API реализован отдельно в CRM: публичный список доступных модулей и начало обмена; внутренний broker на непубликуемом порту 3901 принимает отдельные peer credentials адаптеров. `gateway/` реализует browser-bound PKCE callback, шифрованное серверное хранение native cookies, проверку membership/revision для HTTP/SSE/WebSocket и устойчивый отзыв. Browser получает только host-only AVA cookie. Флаги покупателей и изолированного provisioning до приёмки выключены.

- `onyx/auth/` использует настоящие Community identities и stateful Redis/Postgres стратегии. В двух пустых изолированных БД на закреплённом Onyx-образе проверены создание Basic-пользователя, mint/read/revoke, потерянный mint, disable, private peer HTTP handlers, native cookie dependency и ротация peer key. Это доказательство auth-компонента, **не** полного кабинета, поиска или всех storage ACL. Postgres без доказанной возможности перечислить потерянные токены закрывается в fail-closed режиме; Redis прошёл реальную проверку recovery.
- `onyx/auth/http_guard.py` и `Dockerfile.http` добавляют отдельный guarded HTTP-образ. Проверены 27 auth/guard сценариев и 6 сценариев настоящего main-router `/me` в каждом из двух QA-контуров. Нужны доверенный peer/binding и одна native cookie; revision, expiry, revoke проверяются и при продолжении потока. Тест main-router не запускает lifespan индексации/моделей и не заменяет browser/guest acceptance. Sidecar `Dockerfile` остаётся отдельным.
- `twenty/` содержит Community overlay с обычным `UserSessionService`, собственными identity/binding-записями и guard перед native routes. `qa/` создаёт тестовый workspace штатным onboarding и проверяет конкретную сессию через `/metadata`; HTTP 200 с GraphQL errors не считается успехом. В изолированной QA пройдены mint/readback/restart/revoke. `gateway/qa/twenty-bridge.cjs` также проверил реальную HTTP-цепочку AVA grant → broker → gateway → Twenty и общий выход, без native fixtures. Keycloak/browser/TLS, второй Twenty и рабочие CRM-права остаются отдельными gates.
- `scripts/prepare-native-auth-qa.py`, `run-native-auth-qa.py`, `prepare-twenty-auth-qa.py`, `run-twenty-auth-qa.py` создают и проверяют только явно помеченные пустые QA-контуры. Собственные роли БД не имеют SUPERUSER/CREATEROLE, секреты остаются в закрытых файлах вне Git, наружные порты отсутствуют. QA не подключается к production volumes.

Следующая обязательная часть: настоящий provisioning двух покупателей, scoped storage policies, TLS/Keycloak и сквозная навигация в native UI. Подготовленный Onyx остаётся STAGING до A11/A12/A18. Наличие auth-компонента не заменяет проверку знаний и гостевого сценария.

Лицензии исходных компонентов: [Twenty закреплённой версии](https://github.com/twentyhq/twenty/blob/6da524b8903ec16a3eeea4b2e4a5fb63dbfc1c58/LICENSE), [Onyx v4.7.0](https://github.com/onyx-dot-app/onyx/blob/v4.7.0/LICENSE). Сохраняем уведомления и предоставляем соответствующие исходники модификаций; это не изменение коммерческого кода и не включение платного SSO.
